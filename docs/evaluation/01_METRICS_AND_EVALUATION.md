## 1. The Problem with Traditional Metrics

Before explaining *our* metrics, you must be able to explain why **Accuracy** is
a useless metric for this problem.

**Example:** Our dataset has 38,018 components. Only 2,500 are defective (~6.6%).

If a dumb model rejected *nobody* (always predicts "PASS"), it would achieve:

```
Accuracy = 35,518 / 38,018 = 93.4%
```

That sounds amazing, but it caught **zero defects**. It is completely useless.
This is called the **class imbalance problem**, and it is why we never report
plain Accuracy.

---

## 2. The Vocabulary You Must Know Cold

| Term | Plain English Definition |
|------|--------------------------|
| **True Positive (TP)** | Defective component that we correctly flagged as defective. We caught it. ✅ |
| **False Positive (FP)** | Normal component that we wrongly flagged as defective. We threw away a good part. ⚠️ |
| **True Negative (TN)** | Normal component that we correctly passed. ✅ |
| **False Negative (FN)** | Defective component that we missed. We sent a broken part to space. ❌❌ |

> **Memorize this:** In the context of a satellite, a **False Negative could destroy a spacecraft**.
> A **False Positive** just wastes one cheap semiconductor.

---

## 3. Why We Use F2-Score

The F2-score is a variant of the F-score that weights **Recall higher than
Precision**. Specifically, F2 weights recall 4× more than precision.

**Precision** = "Of everything we flagged, how many were actually defective?"
$$\text{Precision} = \frac{TP}{TP + FP} = \frac{2406}{2406 + 464} = 0.838$$

**Recall** = "Of all actual defects, how many did we catch?"
$$\text{Recall} = \frac{TP}{TP + FN} = \frac{2406}{2406 + 94} = 0.962$$

**F2-Score** formula:
$$F_2 = \frac{5 \times \text{Precision} \times \text{Recall}}{4 \times \text{Precision} + \text{Recall}} = 0.9347$$

**Why F2 and not F1?**
The problem brief explicitly says "a False Negative is catastrophic." F2 encodes
this asymmetric cost directly into the math. Our system is tuned to *sacrifice*
some precision (reject a few extra good parts) to ensure we catch as many defects
as possible.

## 5. Explainability Score

Every AI report the system generates is evaluated against an 8-point rubric.
Our system scored a **perfect 8/8 on all 10 sampled reports**.

The rubric checks that every report contains:
1. Raw trajectory data at all 4 timepoints
2. Numeric SHAP feature contributions
3. References to actual measured values (not just abstract scores)
4. A clear ACCEPT / REJECT / FLAG recommendation
5. Plain-language justification of the anomaly flag
6. Predicted vs actual drift residual
7. Safety-slope comparison
8. Reference to the lot median (batch context)

> **Key caveat to be aware of:** The judges might ask "is this rubric actually
> measuring explainability quality?" The honest answer is: the rubric measures
> *structural completeness* — whether the right data is present — not whether a
> domain expert finds it *useful*. A production system would require human-in-the-loop
> rating by QA engineers.
